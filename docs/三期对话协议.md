# 三期对话协议（SSE）

## 1 建立流

```
POST /api/v1/ai/conversations/{conversation_id}/messages:stream
Authorization: Bearer <token>
Content-Type: application/json

{"content": "门锁没电了怎么办", "client_msg_id": "可选的幂等键"}
```

响应：`content-type: text/event-stream`，头带 `Cache-Control: no-cache`、`X-Accel-Buffering: no`。

> 该路径在服务端**幂等中间件豁免名单**内：中间件在 event-stream 上会提前返回，不写 `COMPLETED`，会给每个流留一条永久 `IN_PROGRESS` 记录。幂等由 `client_msg_id` 在业务层保证。

## 2 事件序列

```
event: meta      data: {"conversation_id":3,"message_id":12,"seq":5,"decision":"ANSWER","intent":"KNOWLEDGE"}
event: ping      data: {}                       # 每 15 秒（模型卡住时）
event: delta     data: {"text":"先用机械钥匙"}
event: citations data: {"hits":[{"document_id":"KB-PROD-QLL3P-MASTER","version":1,
                                 "title_path":"产品知识 / 智能门锁 / 电池续航",
                                 "line_start":14,"line_end":16,"snippet":"…",
                                 "entity_tags":[{"type":"product_line","value":"QL-L3P"}]}]}
event: done      data: {"status":"DONE","latency_ms":1800,"intent":"KNOWLEDGE","decision":"ANSWER","degraded":false}
event: error     data: {"code":"ASSISTANT_GENERATION_FAILED","message":"…","details":null,"request_id":"…"}
```

| 字段 | 说明 |
|---|---|
| `decision` | `ANSWER`（走知识）/ `CLARIFY`（反问）/ `REFUSE`（拒答）/ `SCOPE`（实时事实只给口径）/ `HANDOFF`（转人工） |
| `status` | `DONE` / `REFUSED` / `FAILED` |
| `delta.text` | **只含模型正文**，不含推理内容（服务端丢弃 `reasoning_content`） |

## 3 客户端处理约定

| 事件 | 客户端 |
|---|---|
| `meta` | 立即显示"正在思考…"，并拿到 `message_id` |
| 首个 `delta` | 思考态切换为流式渲染 |
| `ping` | 忽略 |
| `citations` | 渲染引用折叠卡（客户侧**只展示不跳转**） |
| `done` | 结束流；按 `status` 决定是否显示"已中断/拒答" |
| `error` | 气泡标红 + 展示 `code` 与 `request_id`，提供重试（复用同一 `client_msg_id`） |

## 4 断线与重连

不补发（不使用 `Last-Event-ID`）。重连时调用 `GET /ai/conversations/{id}/messages` 拉历史；停滞超过 2 分钟仍为 `STREAMING` 的消息由 `scripts/assistant_cleanup.py` 置为 `FAILED`。

## 5 非流式接口

| 方法 | 路径 | 说明 |
|---|---|---|
| POST | `/ai/conversations/{id}/identity` | 订单号 + 手机后四位；返回 6 字段快照 |
| POST | `/ai/conversations/{id}/handoff` | 用户主动转人工 |
| GET/POST | `/ai/handoffs`、`/{id}/claim`、`/{id}/close` | 客服队列与处理；认领即暂停 AI |
| POST | `/ai/conversations/{id}/agent-messages` | 客服回话，落 `message(role=AGENT)` |
| GET | `/ai/messages/{id}/trace` | 需 `ai:trace:read`；返回计划/意图/命中/引用 |

## 6 人工接管期间的消息

| 步骤 | 接口 | 说明 |
|---|---|---|
| 客服接单 | POST /ai/handoffs/{id}/claim | 置 conversation.ai_paused = true |
| 客户发消息 | POST /ai/conversations/{id}/customer-messages | 只入库给客服，**不调用模型**，返回该 USER 消息 |
| 客户误走流式 | POST /ai/conversations/{id}/messages:stream | 返回 409，code = AI_PAUSED |
| 客服关单 | POST /ai/handoffs/{id}/close（back_to_ai=true） | ai_paused = false，恢复自动回答 |

语义澄清：**ai_paused 关的是模型，不是客户**。接管期间客户必须能继续说话，否则无法与人工沟通。

## 7 实时性说明

- 客户侧轮询当前会话与列表（2s），客服侧轮询会话消息（1.5s）。
- 客服侧能看到的"流式过程"来自服务端进程内的内存缓冲：生成中的回答会把已产出的文本随消息列表返回。
- 该缓冲仅在本进程内有效；多 worker 部署需要改为跨进程广播（四期再做）。
