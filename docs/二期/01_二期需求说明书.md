## 1 二期目标与边界

**目标**：把企业知识从散落的 Markdown 变成「可治理、可发布、可回滚、可追溯」的知识资产，并提供检索能力与检索测试入口。

| 做 | 不做（属三/四期） |
|---|---|
| 文档导入、元数据、版本、审核、发布、归档、回滚 | 对话式问答、会话管理、意图识别 |
| 结构化规则存储、冲突检测、发布门禁 | 规则运行时求值、策略编排 |
| 切片、向量化（本地 bge-small-zh-v1.5）、混合检索 | RAG 生成、引用润色、多轮改写 |
| 检索测试页（TopK、过滤、命中片段） | 客服身份核验、转人工、SSE/WebSocket |
| 治理看板（重复/过期/孤立/冲突） | 本体建模、工具调用、工作流、评测闭环 |

二期的产出必须能直接被三期消费：**检索服务 + chunk 元数据 + 动态事实服务 + 事件出口**。

## 2 知识范围与首批素材

覆盖 16 个业务域：企业基础、产品知识、订单支付与发票、物流与履约、安装与交付、退换货与退款、保修维修与备件、账户设备与家庭共享、云服务与订阅、客服 SOP、工单投诉与升级、隐私安全与高风险场景、场景案例、结构化规则、主题手册、校验与维护。

首批素材：仓库内 `knowledge_raw/`（169 篇 Markdown，已按 16 个目录组织，每篇带 `document_id`、`version`、`owner`、`status` 等 front matter）。

首批产品：QL-L3P 智能门锁、QC-C2G 家用摄像头、QR-R5M 扫地机器人、QT-L1C 智能吸顶灯、QH-G1 家庭网关、配件耗材（QA-L3-BAT8、QA-R5-BRUSH）。

### 4.3 维度必须改一处（重要）

`knowledge.chunk.embedding` 现在是 `vector(1024)`，而 `bge-small-zh-v1.5` 输出 **512 维**。二期第一步就要改成 `vector(512)`：

    ALTER TABLE knowledge.chunk ALTER COLUMN embedding TYPE vector(512);
    DROP INDEX IF EXISTS knowledge_chunk_hnsw_idx;
    CREATE INDEX knowledge_chunk_hnsw_idx ON knowledge.chunk USING hnsw (embedding vector_cosine_ops) WITH (m = 16, ef_construction = 64);

当前该表无数据，改列安全。若将来换 1024 维模型（如 bge-m3），再改回并重建索引，并**重算全部向量**（写进运维手册）。

## 5 功能需求（逐模块）

### 5.1 导入（/knowledge/import）

| 项 | 要求 |
|---|---|
| 支持格式 | 一期先 Markdown / TXT / DOCX；PDF / XLSX / CSV / HTML 放到二期后段（解析依赖重） |
| 批量 | 一次可传多个文件；单文件上限 20MB（沿用一期附件限制） |
| 解析 | 提取 front matter（document_id、title、category、owner、version、effective_date、status）+ 正文 Markdown |
| 幂等 | 以文件 sha256 去重：同 checksum 已导入则跳过并提示；重复导入不产生新版本 |
| 失败 | 解析失败进入错误清单（文件名、原因、行号），不阻塞其他文件 |
| 结果 | 生成 document（DRAFT）+ document_version（DRAFT, version=1 或 N+1）+ import_job 记录 |

**验收点**：169 篇 `knowledge_raw` 可一次批量导入；重复导入 0 新增；故意坏文件进错误清单且其他文件成功。

### 5.2 元数据（文档详情侧栏）

必填：document_id、title、category、owner、status。选填：product_scope（型号或产品线）、channel_scope（渠道编码数组）、region、effective_date、tags。

规则：`document_id` 全局唯一（同租户内）；`category` 取 16 个业务域的固定枚举；`channel_scope` 空数组表示全渠道。

### 5.3 版本与发布

状态机（沿用一期风格，text + CHECK）：

    DRAFT → REVIEWING → SCHEDULED → ACTIVE → ARCHIVED
                      ↘ FAILED / 退回 DRAFT

| 规则 | 说明 |
|---|---|
| 单一 ACTIVE | 同一文档同一时刻只能一个 ACTIVE（已有部分唯一索引，必须处理冲突：发布新版本时旧版本转 ARCHIVED） |
| 定时生效 | `effective_from` 在未来 → 状态 SCHEDULED，由后台任务到点转 ACTIVE |
| 回滚 | 选择历史版本 → 生成新版本（内容复制，version 递增），不覆盖历史 |
| 发布门禁 | 规则冲突未解决、checksum 未变、切片为空、必填元数据缺失 → 拒绝发布并返回原因清单 |
| 发布弹窗 | 必须展示：变更摘要、影响范围（哪些产品/渠道）、引用数量（该文档被三期问答引用的次数，二期先返回 0 并留字段）、回滚目标版本 |

### 5.4 结构化规则（/knowledge/editor 的规则页签）

规则 = `rule_id` + 条件 + 动作 + 禁止事项 + 例外 + 优先级 + 生效期。

| 字段 | 类型 | 说明 |
|---|---|---|
| rule_id | varchar(48) | 唯一，形如 KB-RULE-0001 |
| condition | jsonb | 结构化条件：产品线/问题类型/身份/订单状态/时间窗 |
| action | jsonb | 允许的结论或动作（如「30 天内可退」「需上门检测」） |
| forbid | jsonb | 明令禁止项（如「不得远程开锁」） |
| priority | int | 数值越大越优先；同优先级冲突要上报 |
| status/effective | 同文档 | ACTIVE 规则优先于文档（真源优先级） |

冲突检测：同一 `conflict_group` 内 condition 有交集且 action 不一致 → 生成 `rule_conflict`（severity: BLOCK/WARN）；**BLOCK 未解决时禁止发布**。

二期只做存储 + 冲突检测 + 门禁，**不做运行时求值**（属三期策略层）。

### 5.5 切片与向量化

| 项 | 要求 |
|---|---|
| 切分策略 | 按 Markdown 标题层级切：一级标题为域、二级为章节；单切片 200–600 字，超长按段落二次切；保留 `title_path`（如「产品知识 / 智能门锁 L3 Pro / 电池续航」） |
| 特殊块 | 表格转为「表头: 值」文本并保留行号；步骤清单保留序号；问答对按 Q/A 成对切 |
| token_count | 按字符数近似（中文 1 字≈1 token），用于预算与截断 |
| embedding | 本地 `BAAI/bge-small-zh-v1.5`，512 维，L2 归一化，cosine |
| 元数据 | chunk.metadata 存 `source_line_start/end`（原文位置）、`headings`、`doc_version`、`product_scope`、`effective_until` |
| 增量 | 版本发布时重建该版本的切片；旧版本切片保留（回滚可用），检索只查 ACTIVE 版本 |
| 异步向量化 | 切片先落库（embedding_status=PENDING），由后台 worker 批量补向量并置 READY；失败置 FAILED 可重试，检索只查 READY |
| worker 与重算 | scripts/knowledge_worker.py（FOR UPDATE SKIP LOCKED 取任务）；scripts/reindex_embeddings.py（分批、断点续跑，换模型时用） |

**验收点**：任意命中片段都能回指 `document_id + version + title_path + 原文行号`。

### 5.6 审核（/knowledge/review）

| 项 | 要求 |
|---|---|
| 提交审核 | 编辑提交 → 生成 review_task（assignee 按 category 分配给审核员） |
| 批注 | 支持锚定到 title_path / chunk / 字符区间；可回复、可标记已解决 |
| 决定 | 通过（APPROVED）/ 退回（CHANGES_REQUESTED）/ 拒绝（REJECTED），必须填理由 |
| 冲突提示 | 审核页展示该文档的规则冲突与重复文档提示 |
| 审计 | 每次提交/批注/决定写 audit_log（before/after、actor、request_id） |

### 5.7 检索测试（/knowledge/retrieval-test）

输入：查询文本、产品、业务域、身份等级、渠道、TopK（默认 10）。输出：命中列表（chunk 摘要 + 打分 + title_path + document_id/version + 原文行号），以及耗时。

检索实现（二期做混合检索）：

1. 过滤：只查 ACTIVE 版本、未过期（effective_until 为空或 > now）、产品/渠道/业务域命中；
2. 全文：`tsv` 用 `plainto_tsquery('simple', ...)`，`content` 用 `similarity()`；
3. 向量：查询侧加 bge 中文指令前缀「为这个句子生成表示以用于检索相关文章：」，取 `embedding <=> query_vec` 最近 N 个；
4. 融合：RRF（k=60）合并两路结果，或 0.6*向量排名 + 0.4*全文排名；阈值 cosine < 0.35 丢弃；
5. 返回：TopK + 每路原始分数 + 命中路径；写 retrieval_log。

### 5.8 治理（/knowledge/governance）

| 报告 | 判定 |
|---|---|
| 重复 | 标题相似度 > 0.9 或内容 simhash 距离 < 3 |
| 过期 | effective_until < now 仍为 ACTIVE；或 12 个月未更新 |
| 孤立 | 无入链引用（二期用 rule.document_pk 与文档内链） |
| 冲突 | rule_conflict 未解决、同 document_id 多 ACTIVE 尝试 |
| 完整性 | 缺 owner/category/product_scope/切片为空的文档 |

看板输出可下钻到文档列表；每周可由后台任务生成快照（写 retrieval_log 或独立表，二期用报告接口实时算即可）。

## 8 非功能要求

| 项 | 要求 |
|---|---|
| 性能 | 文档列表 P95 < 300ms；检索测试（10 万切片内）P95 < 1.5s；导入 100 篇 < 3 分钟 |
| 幂等 | 写接口幂等键；导入按 checksum 去重；发布重复调用返回同一结果（幂等键） |
| 审计 | 文档/版本/规则/审核的全部写操作写 audit_log，含 before/after |
| 事件 | 发布、归档、回滚、切片完成写 `shared.outbox_event`（供三期消费） |
| 可观测 | 检索接口记录 latency、命中数、过滤条件；导入任务有进度与错误数 |
| 安全 | 不落密钥；上传文件按一期附件校验（扩展名 + MIME + magic + sha256）；越权访问返回 404 |
| 兼容 | 不改一期表结构与接口；新增列/表/索引；前端不改一期页面 |

## 9 验收标准（总）

1. 169 篇企业知识材料完成导入、分类、版本化；重复导入不产生重复文档。
2. 任意回答片段可追溯到 document_id、version、title_path、原文行号。
3. 规则冲突（BLOCK 级）阻止发布；过期内容不进默认检索。
4. 发布、归档、回滚、权限变更均有审计记录，可查 request_id。
5. 检索测试页能对同一查询给出向量/全文/融合三路分数，且过滤条件生效。
6. 治理看板四类报告有真实数据，可下钻。
7. 全量测试通过（一期 53 项 + 二期新增），契约校验 0 问题，前端 tsc/build 通过。
8. 二期结束时验收清单 L1–L8 的「预埋审查」全部通过（三/四期要用的接口与表结构已就位，但未实现）。

### A.2 第四期：本体、工具与评测
