## 1 目标与边界

**目标**：让三期"能答"的客服变成"能查、能办、可度量"——用本体把实体关系补齐，用工具把一期业务能力接进对话，用评测集把"没变差"变成可执行的门禁。

| 做 | 不做 |
|---|---|
| `ontology` schema 5 表（实体/关系/别名/标签/切片映射）+ 审核态 | 引入图数据库（Neo4j 等） |
| 本体→检索：**检索前**实体归一（映射到二期已有 `filters.product_scope`）+ **检索后**深度 1 扩展 | 本体多跳（深度 ≥2）用于检索；深度 2 仅用于回答取证 |
| 9 个工具（7 只读 + 2 写）+ JSON Schema + `ToolSpec` 单真源注册表 | 金额类写操作（退款执行、开票执行） |
| 写操作安全模型：待确认动作 + 二次确认 + 幂等 + 3 时点审计 + 频次闸 | 模型无确认直接执行写操作 |
| 核验↔工具门禁；**修复三期 `identity_level` 客户端可控缺陷（F21）** | 游客/未登录调用业务工具 |
| 单段流式 + 叙述缓冲 + 2 个新 SSE 事件 | 改老三期 6 个 SSE 事件的载荷 |
| 评测 60 条 YAML + L1 确定性门禁（`make test`）+ L2 真实模型记录 | LLM-as-judge；状态机/角色/渠道入本体 |

**与三期衔接**：沿用 `assistant` schema 已有 6 表与 `ToolSpec` 骨架；沿用"引用只由服务端生成"的硬约束；沿用 `active_verification()` 作为核验唯一真源（三期定义了但无调用点）。
**与二期衔接**：只调 `knowledge_retrieval.search()`，且**只传它已支持的 filter 键**（`category`/`product_scope`），二期检索代码**零改动**。
**与一期衔接**：只调服务层函数（`order`/`aftersales`/`payment`/`fulfillment`/`invoice`/`catalog`），**不直连数据库**；接受"一期服务自带 `db.commit()`"的边界，写路径拆两段事务。

## 3 角色与权限

新增 7 个三段式权限码（追加式，登记到 `shared.app_permission`）：

| 权限码 | 含义 | 授予角色 | 说明 |
|---|---|---|---|
| `tool:read` | 允许触发只读工具 | `AI_AGENT`、`AI_SUPERVISOR` | 不授予客户（客户无需权限码） |
| `tool:write:order` | 允许触发 `cancel_order` | `AI_SUPERVISOR` | 灰度时按渠道再收窄 |
| `tool:write:aftersales` | 允许触发 `create_after_sales` | `AI_SUPERVISOR` | 同上 |
| `tool:admin` | 维护工具开关与查看评测报告 | `SUPER_ADMIN` | 无新角色 |
| `ontology:read` | 查看实体/关系/别名 | `KNOWLEDGE_EDITOR`、`KNOWLEDGE_ADMIN` | 后台只读 |
| `ontology:write` | 维护实体/关系/别名 | `KNOWLEDGE_ADMIN` | 写本体 |
| `ontology:review` | 审核导入候选 | `KNOWLEDGE_REVIEWER`、`KNOWLEDGE_ADMIN` | 审核态流转 |

**客户侧不使用权限码**：一期服务函数已全部按 `actor.party == 'CUSTOMER'` → `customer_id` 过滤，"客户只能操作自己的单据"由服务层天然保证。四期唯一要守住的是：**`actor` 只来自 `conversation.user_id`，永不来自工具参数**。

## 4 数据模型

### 4.1 新 schema `ontology`（5 表）

| 表 | 关键列 | 约束 |
|---|---|---|
| `entity` | `code`(text，如 `QL-L3P`)、`kind`(product/part/fault/action/policy/accessory)、`name`、`summary`、`attrs jsonb`、`status`(DRAFT/APPROVED/DEPRECATED)、`source`(manual/import) | `UNIQUE(tenant_id, code)` |
| `relation` | `src_entity_id`、`dst_entity_id`、`predicate`(PART_OF/SYMPTOM_OF/REMEDY/COVERED_BY/GOVERNED_BY/ESCALATES_TO)、`weight`、`status`、`source` | `UNIQUE(tenant_id, src_entity_id, predicate, dst_entity_id)`；禁止自环 |
| `alias` | `entity_id`、`alias`(自然语言/口语/错别字)、`confidence`(HIGH/LOW)、`status` | `UNIQUE(tenant_id, alias, entity_id)` |
| `entity_tag` | `entity_id`、`tag`(如 `product_line`/`rule_id`)、`value` | 用于把本体映射到二期 `filters.product_scope` |
| `chunk_entity` | **`document_id`、`version`、`chunk_ord`**（逻辑键）、`chunk_id`(冗余加速)、`entity_id`、`method`(alias/regex/manual)、`confidence`、`status` | `UNIQUE(document_id, version, chunk_ord, entity_id)`；**不挂 `chunk_id` 作主键**，换版按逻辑键重挂 |

> 逻辑键的原因：文档发新版会产生新的 `document_version_id` 与新 chunk 行（`UNIQUE(document_version_id, ord)`），挂 `chunk_id` 会让映射指向死行。

### 4.2 `assistant` schema 追加（2 表，6 → 8）

| 表 | 关键列 | 约束 |
|---|---|---|
| `pending_action` | `conversation_id`、`message_id`、`action_key`、`tool_name`、`args jsonb`、`summary`、`impact`、`irreversible`、`status`、`expires_at`、`executed_at`、`result jsonb`、`error_code` | `UNIQUE(conversation_id, action_key)`；`UNIQUE(conversation_id, message_id)`（单轮仅 1 写） |
| `tool_call` | `message_id`、`conversation_id`、`tool_name`、`args jsonb`（**脱敏**）、`status`、`latency_ms`、`error_code`、`proposal_id` | 按 `message_id` 索引 |

`pending_action.status`：`PROPOSED / CONFIRMED / EXECUTED / FAILED / EXPIRED / CANCELLED`
`tool_call.status`：`OK / FAILED / REJECTED / TIMEOUT`

### 4.3 表数账

| 阶段 | 表数 |
|---|---|
| 一/二/三期 | 61 |
| +`ontology` 5 表 | 66 |
| +`assistant.pending_action` / `assistant.tool_call` | **68** |
| 不建表 | 工具注册表（代码单真源）、评测用例（`eval/cases/*.yaml`）、评测报告（`var/`，已 gitignore） |

### 4.4 状态机

| 对象 | 流转 |
|---|---|
| `pending_action` | `PROPOSED → CONFIRMED → EXECUTED`；`PROPOSED → CANCELLED`；`PROPOSED →(10min) EXPIRED`；`CONFIRMED → FAILED →（人工重试）` |
| 契约 | 所有迁移用 `UPDATE … WHERE status='<from>'` 做 CAS，禁止读改写 |

**可撤销性**：`cancel_order` 执行后**不可撤销**（无反向操作）；`create_after_sales` 在 `COMPLETED` 前可由客户自行 `aftersales.cancel` 撤销，AI 只提供入口不代操作。
**单轮写约束**：一期服务各自 `db.commit()`，多写无法回滚 → **单轮最多 1 个写工具**，复合写必须拆两轮确认。

### 5.5 写操作安全

| # | 需求 |
|---|---|
| 5.5.1 | 写工具只生成 `PROPOSED`，**不改业务数据**；确认后由独立请求执行 |
| 5.5.2 | 确认卡片只展示：对象摘要（复用 `order_fact_snapshot` 6 字段白名单）、影响、是否可撤销、过期时间；**不展示完整手机/地址/卡号/其他单号** |
| 5.5.3 | 幂等：`action_key = sha256(tool + 归一化参数)`，`UNIQUE(conversation_id, action_key)`；状态迁移用 CAS |
| 5.5.4 | 审计 3 时点：`ai.action.propose/confirm/execute`；事件 `ai.action.proposed/confirmed/executed/failed` |
| 5.5.5 | 频次闸：单会话写操作 ≤3 次；同一 order 24h 内取消 ≤1 次 |
| 5.5.6 | 10 分钟未确认 → `EXPIRED`，执行接口拒绝 |
| 5.5.7 | 执行前二次校验 `order.customer_id == conversation.user_id` 对应客户 |
| 5.5.8 | 写执行**绝不自动重试**；失败消息明确"未做任何改动" |

### 5.6 身份核验与工具门禁

| # | 需求 |
|---|---|
| 5.6.1 | `requires_identity=True` 的工具在**进入工具节点前**检查 `active_verification(conversation_id)`；未核验返回 `IDENTITY_REQUEST`，工具零执行 |
| 5.6.2 | 核验单的 `order_no` 必须与工具入参**精确匹配**；核验 A 单查 B 单视为未核验 |
| 5.6.3 | 读工具沿用 30 分钟 TTL；写工具在 `confirm` 时**再校验一次** `expires_at` |
| 5.6.4 | **修复 F21**：`identity_level` 由服务端推导（VERIFIED→`customer`，否则 `public`；员工带 `ai:chat:read` 才给 `agent`），**忽略客户端入参** |
| 5.6.5 | 3 次失败锁 → 转人工 `IDENTITY_FAILED`，沿用不改 |

### 5.7 失败与降级

| 情形 | 回话 | 重试 | 转人工 |
|---|---|---|---|
| 超时（读 3s / 写 8s） | "查询超时，请稍后再试或转人工" | 否 | 可选 |
| 5xx | "系统繁忙，已记录" + `request_id` | 只读 1 次 | 是 |
| 业务拒绝（`ORDER_STATE_INVALID`） | 原样透传 code + 人话 + 出路 | 否 | 否 |
| 404 / 越权 | 统一"没有找到该订单" | 否 | 否 |
| 参数不合法 | 反问补全 | 否 | 否 |
| 写执行失败 | "未能完成，未做任何改动" + `request_id` | **否** | 可选 |

**防编造铁律**：工具结果是**服务端事实块**，前端直接渲染成卡片；模型只写叙述句，**不得复述金额/单号/时间**。`finish_reason=length` 判为失败（非"空回答"）。

### 5.8 流式事件扩展

沿用 `meta → (ping)* → delta* → citations → done | error`，**新增 2 个事件，老 6 个载荷一字不改**：

| 事件 | 载荷 | 用途 |
|---|---|---|
| `tool` | `{name, status: running\|ok\|failed, latency_ms}` | "正在查询订单…"骨架 |
| `action` | `{id, tool, summary, impact, irreversible, expires_at}` | 确认卡片 |

**形态**：单段流式 + 首轮叙述缓冲（B2）——带 `tools` 的轮次里 `content` 先缓冲，`finish_reason=tool_calls` 时先发 `tool` 事件、执行、再把缓冲叙述随结果一起下发；纯文本则全量下发。**`tool_calls` 原始 JSON 永不出现在任何 SSE 事件中。**

## 7 非功能

| # | 项 | 要求 |
|---|---|---|
| 7.1 | 首字节 | 知识类（规则 fast-path）**不进决策阶段**，TTFT 与三期持平；事实类目标**待实测后定**（本期只有"决策到达 690ms"数据，不预设端到端数字） |

| 7.6 | 审计与事件 | 所有写路径 3 时点 `audit_log`；`ai.tool.*` / `ai.action.*` 进 `shared.outbox_event` |
| 7.7 | 隐私 | `tool_call.args` **脱敏后**存；不落 prompt 全文；确认卡片不含完整手机/地址/卡号 |
