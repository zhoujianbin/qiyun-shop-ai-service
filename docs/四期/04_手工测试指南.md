# 四期手工测试指南

> 用途：你按这一份走一遍就够。环境为本地 dev 库（`qiyun_shop_dev_3`，已迁移 0009–0011、已灌本体与 `product_scope`）。
> 自动化门禁见文末；本文件只讲**手工怎么点、该看到什么**。

## 0 启动

```bash
make run                      # http://127.0.0.1:8000（已带 --reload）
```

前端由后端托管已构建产物；改了前端代码才需要 `cd web && npm run build`。

## 2 A 组｜本体归一 + 检索收窄（客户）

进入 `/assistant` → 新对话，依次问：

| 问法 | 应看到 | 说明 |
|---|---|---|
| `指纹识别差怎么办` | 正常作答 + 「引用 5 条」；引用标签含 `QL-L3P`、`SYM-QL-L3P-02` | 实体归一 → 只查 L3P 产品文档 |
| `QL-L3P 门锁电池能用多久` | 引用含 `WARRANTY-QL-L3P-*` | 编码直命中 + 本体标签 |
| `电池鼓包了怎么办` | 正常作答，但**不收窄产品** | 故障是跨产品概念 |
| `门锁没电了怎么办` | 不被误判成具体型号 | 上位词不误判 |
| `怎么退款` | 正常作答 | 零实体 → 原样检索（对照） |

后端留痕：消息 `metadata.ontology` 里应有 `entities` 与 `product_scope`（如 `QL-L3P`）；`GET /api/v1/ai/messages/{id}/trace` 可看意图与命中数。

## 3 B 组｜只读工具 + 核验门禁（客户）

| 步骤 | 应看到 |
|---|---|
| 未核验直接问 `我的订单 QY20261017182947766126 到哪了` | 回「需要先核验身份…」，**不编造任何订单信息** |
| 点右上「核验身份」→ 订单号 `QY20261017182947766126` + 后四位 `0001` | 顶部出现「已核验订单 …（有效期至 …）」 |
| 再问 `我现在核验过了，帮我查下订单号 QY20261017182947766126 的订单状态` | 返回状态/金额/下单时间/履约状态（来自业务系统） |
| 换一个不属于自己的订单号再问 | 统一「没有找到该订单」，不区分"不存在/无权" |

## 4 C 组｜写操作（客户，已默认可自助）

前提：会话已核验、订单可取消（PENDING_PAYMENT）。

| 步骤 | 应看到 |
|---|---|
| 问 `帮我取消订单 <订单号>` | 出现**黄色确认卡片**：摘要（含当前状态）、影响说明、红色「确认后不可撤销」、状态 `PROPOSED`、有效期 |
| 点「取消」 | 卡片置 `CANCELLED`，订单**未变** |
| 重新发起后点「确认执行」 | 卡片置 `EXECUTED`，订单变 `CANCELLED` |
| 对已完成订单发起取消 | 模型应**不生成卡片**，改为引导走退货退款（工具的"何时不要用"生效） |
| 10 分钟后再确认（另开一次） | 提示动作已过期，订单不变 |

留痕 SQL：

```sql
select tool_name,status,error_code from assistant.tool_call order by id desc limit 5;
select id,tool_name,status,summary,expires_at from assistant.pending_action order by id desc limit 5;
select action,resource_type from shared.audit_log where action like 'ai.action.%' order by id desc limit 6;
select event_type from shared.outbox_event where event_type like 'ai.action.%' order by id desc limit 6;
```

## 5 D 组｜后台本体维护（管理员）

新窗口登录 `admin` → 知识库 → **本体维护**（`/admin/knowledge/ontology`）：

| 操作 | 应看到 |
|---|---|
| 打开页面 | 83 条实体，类型/状态/来源列，默认按 `kind, code` 排序 |
| 类型筛选「产品」+ 状态「APPROVED」 | 只剩 5 个产品 |
| 勾选若干条 → 「审核通过」 | 对应实体状态变 APPROVED（只对 DRAFT 有意义） |
| 点任一实体「看图谱」 | 右侧抽屉显示根实体、邻接数、深度 1/2 与谓词（如 `PART_OF`、`COVERED_BY`） |

> 图谱是**无向邻域**：从配件出发会经产品再走到该产品的其它部件，这是设计选择（便于发现同一产品下的关联），不是有向路径。
