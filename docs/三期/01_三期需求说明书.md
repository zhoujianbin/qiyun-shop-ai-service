## 1 目标与边界

**目标**：让客户在商城内就能"问得出口、答得有据、答不了有人接"——RAG 问答 + 流式对话 + 身份核验 + 转人工，且每条回答可回指到二期已发布的切片。

| 做 | 不做（属四期） |
|---|---|
| 会话与消息、SSE 流式 | 通用工具注册表与写操作式工具调用 |
| 意图识别（4 类）+ plan-and-execute（计划 ≤2 步） | 多步任务编排（门锁故障→上门→备件） |
| 引用装配（服务端从命中生成）与无引用拒答 | 本体建模与实体链接 |
| 身份核验（订单号+手机后四位）+ 固定事实快照 | 评测集、回归门禁、A/B |
| 转人工（5 类触发、认领制） | 语音/图片消息、多客服排队与 SLA |
| 客服工作台 + 客户对话页（微信式） | — |

**与二期衔接**：直接 `import knowledge_retrieval.search()`；引用只用 `hits` 稳定字段；知识只来自 ACTIVE 版本。

## 3 角色与权限

新增 5 个三段式权限码（登记到 `shared.app_permission`，`module='ai'`）：

| 权限码 | 含义 | 授予角色 |
|---|---|---|
| `ai:chat:read` | 读取会话与消息（客服侧） | `AI_AGENT`、`AI_SUPERVISOR` |
| `ai:chat:write` | 以客服身份回话、结束会话 | `AI_AGENT`、`AI_SUPERVISOR` |
| `ai:handoff:read` | 查看转人工队列 | `AI_AGENT`、`AI_SUPERVISOR`、`CS_SUPERVISOR` |
| `ai:handoff:write` | 接单、关单 | `AI_AGENT`、`AI_SUPERVISOR` |
| `ai:trace:read` | 查看问答链路留痕 | `AI_SUPERVISOR` |

新增角色：`AI_AGENT`（客服席）、`AI_SUPERVISOR`（客服主管，含留痕）；`CS_SUPERVISOR`（一期已有）追加 `ai:handoff:read`。
客户侧会话只用客户 token，不占用上述权限码。

## 4 数据模型

新 schema `assistant`，6 张表；**库内表数 55 → 61**，`knowledge`/`commerce`/`shared` 零改动。

| 表 | 关键列 | 约束 |
|---|---|---|
| `conversation` | `conversation_no`(seq("CV"))、`user_id`(NOT NULL)、`party`(CUSTOMER/GUEST)、`channel_account_id`、`title`、`status`(OPEN/CLOSED)、**`ai_paused`**、`message_count`、`last_message_at` | `UNIQUE(tenant_id, conversation_no)` |
| `message` | `conversation_id`、`seq`、`role`(USER/ASSISTANT/**AGENT**/SYSTEM)、`content`、`status`(STREAMING/DONE/FAILED/REFUSED)、**`client_msg_id`**、`model`、`prompt_tokens`、`completion_tokens`、`latency_ms`、`metadata jsonb`(`plan`/`feedback`) | `UNIQUE(conversation_id, seq)`；`UNIQUE(conversation_id, client_msg_id) WHERE NOT NULL` |
| `citation` | `message_id`、`chunk_id`、`document_id`、`version`、`title_path`、`line_start`、`line_end`、`snippet`、`rank`、**`entity_tags jsonb`** | `UNIQUE(message_id, rank)` |
| `handoff` | `conversation_id`、`reason`(5 枚举)、`status`(OPEN/CLAIMED/CLOSED)、`assignee_id`、`claimed_at`、`closed_at`、`summary` | `UNIQUE(conversation_id) WHERE status IN ('OPEN','CLAIMED')` |
| `identity_verification` | `conversation_id`、`order_no`、`phone_tail char(4)`、`order_id`、`customer_id`、`status`(VERIFIED/FAILED)、`attempts`、`expires_at` | 只存手机后四位 |
| `retrieval_trace` | `message_id`、`query`、`filters`、`intent`、`hit_count`、`hits`、`latency_ms`、`model`、`tokens` | 随会话级联删除 |

**状态机**

| 对象 | 流转 |
|---|---|
| conversation | `OPEN → CLOSED`；`ai_paused` 与 handoff 联动（CLAIMED→true，退回/关闭→false） |
| message | `STREAMING → DONE / FAILED / REFUSED`；超 2 分钟仍 STREAMING 由清理任务置 FAILED |
| handoff | `OPEN → CLAIMED → CLOSED`；`OPEN → CLOSED`（取消） |

**幂等与序号**：`client_msg_id` 唯一键兜底重发；`seq` 用会话行锁 + `message_count+1`，保证会话内连续无空洞。

## 5 功能需求

### 5.1 会话与消息

| 项 | 要求 |
|---|---|
| 创建 | 登录客户或游客（`guest-session`）均可创建；`party` 记录身份类型 |
| 关闭 | 客户可结束；关闭后追加消息返回 409 |
| 上下文 | 只取最近 `ASSISTANT_CONTEXT_ROUNDS`（默认 6）轮 + 本次命中；更早消息保留但不用 |
| 容量 | 单消息 ≤2000 字；单会话 ≤200 条；单用户每分钟 ≤20 次问答（超限 429） |
| 保留 | 已关闭会话超保留期（默认 90 天）由 `scripts/assistant_cleanup.py` 级联删除 |

### 5.2 流式（SSE）

事件序列固定：`meta → (ping)* → delta* → citations → done | error`

| 事件 | 载荷 |
|---|---|
| `meta` | `{conversation_id, message_id, seq}` |
| `ping` | `{}`，每 15s |
| `delta` | `{text}`，只含 `content`，**不含推理内容** |
| `citations` | `{hits:[{document_id,version,title_path,line_start,line_end,snippet}]}` |
| `done` | `{status, tokens:{prompt,completion}, latency_ms}` |
| `error` | `{code,message,details,request_id}` |

实现约束：POST + `fetch` 读流（不用 EventSource）；鉴权走 `Authorization`；响应头 `Cache-Control: no-cache`、`X-Accel-Buffering: no`；端点加入中间件幂等豁免。

### 5.3 RAG 编排（plan-and-execute）

| 项 | 要求 |
|---|---|
| 图 | `plan → execute ⇄ replan → finalize` 三节点一回路；不用 checkpointer |
| 意图 | 4 类：`KNOWLEDGE`/`REALTIME_FACT`/`IDENTITY_REQUEST`/`HUMAN_REQUEST`；**规则词表优先，未命中才调 LLM**（保护首 token 时延） |
| 计划 | 严格 JSON + Pydantic 校验；非法即弃用并退化为固定两步；**上限 2 步** |
| 重试 | 零命中时允许**改写查询重试 1 次**；仍空则拒答 |
| 闸门 | 最大 4 步、最多 1 次 replan、单次问答总超时 30s |
| 工具 | 三期只注册 `search_knowledge`（read_only=true）；四期加工具不改图 |

### 5.4 引用与拒答（硬约束）

1. 引用**只由服务端从 `hits` 生成**，不解析模型输出。
2. 无命中 → **不调模型**；先反问澄清一次，仍无命中则固定拒答 + 建议转人工。
3. 拒答文本 **不得** 出现具体参数、时限、金额。
4. 有命中但属实时事实类且未核验 → 只答口径，**不给数值**。
5. 有命中但相关度一般 → 回答前缀「以下为一般口径，具体以你的订单为准」。

### 5.5 身份核验

| 项 | 要求 |
|---|---|
| 触发 | 意图属 5 类之一：订单查询 / 物流 / 退款进度 / 发票 / 设备绑定 |
| 凭据 | 订单号 + 收货手机后四位（比对 `commerce.orders.receiver_phone`） |
| 通过后 | 会话级只读放宽；可给**固定事实快照**：订单号、状态、实付金额、下单时间、物流状态+运单号、售后进度 |
| 失败 | 统一话术（不区分"订单不存在"与"手机不符"）；连续 3 次失败 → 强制转人工 |
| 过期 | 核验 30 分钟有效，过期按未核验处理 |
| 红线 | 永不展示：完整手机号、完整地址、支付卡号、身份证、其他订单、设备密码/开锁凭证 |

### 5.6 转人工

| 触发原因 | 说明 |
|---|---|
| `USER_REQUEST` | 用户明确要求 |
| `HIGH_RISK_RULE` | 命中 escalation 规则（`triggers` 词表匹配），取该规则 `forbid` 作为安全提示 |
| `IDENTITY_FAILED` | 核验连续 3 次失败 |
| `NO_HIT` | 同一问题追问第二次仍无命中 |
| `MODEL_ERROR` | 模型超时/异常 |

规则：进 `OPEN` 队列 → 客服认领 `CLAIMED`（**同时置 `ai_paused=true`，AI 停止自动回答**）→ 客服回话写 `message(role=AGENT)` → 关单必填结论 → `CLOSED`。
**不自动建售后工单**（会话与工单解耦）。

### 5.7 客服工作台与客户对话页

| 页面 | 要求 |
|---|---|
| 客户对话页 `/assistant` | 微信式：左右气泡、首字头像、>5 分钟时间分隔、思考动画→流式、引用折叠卡、快捷问题、Enter 发送/Shift+Enter 换行、上滑加载历史、失败重试、点赞点踩 |
| 入口 | 独立页；`CustomerShell` 挂一个入口按钮跳该路由（浮窗不复制对话逻辑） |
| 客服工作台 `/admin/assistant` | 左会话/待接列表（最近时间、消息数、转人工状态），右对话窗口可接管回话；引用侧栏；接单/关单 |
| 引用跳转 | **客户侧只展示不跳转**（`/admin/knowledge/documents/:id` 需员工权限，客户点会 403） |

## 9 验收标准（总）

1. 客户能建会话并收到流式回答，事件序列符合 §5.2。
2. 每条回答至少一条引用，且引用可回指到二期切片（document_id + version + 行号）。
3. 无命中时不调用模型，回答不含具体参数/时限/金额。
4. 问订单/物流类问题未核验时被拦；核验失败话术统一；连续 3 次失败自动转人工。
5. 客服能在工作台接单并回话，接单后 AI 停止自动回答。
6. 流中断有错误事件；重连后历史可拉取；僵尸 STREAMING 被清理为 FAILED。
7. 十字段埋点齐全，可按 message 反查 trace。
8. 一期 53 项测试与二期全部测试保持通过；表数 61；`check_frontend_contract.py` problems=0。
