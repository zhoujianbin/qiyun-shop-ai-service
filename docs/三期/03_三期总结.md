## 6 收口补丁（phase3-assistant-fix / phase3-assistant-sessions）

三期归档后又做了两轮：一轮修真实走查暴露的缺陷，一轮改掉"客户侧不做多会话"的边界。

### 6.1 修的缺陷

| # | 缺陷 | 修法 |
|---|---|---|
| P0 | 对话里说"我要转人工"不入库，客服队列看不到 | decision == HANDOFF 时创建 handoff（与其余触发共用幂等约束） |
| P1 | 普通问题首字 3–6 秒 | 意图规则未命中不再调模型（规划开关默认关）；实测首字降到约 1.6 秒 |
| P2 | 高危问题漏护栏 | 别名表补真实说法（陌生人访问/被偷看/漏电/锁死/异地登录…）+ 真实问句回归 |
| P3 | 无关问题也配 5 条无关引用 | 相关性闸门（问题与命中切片关键词重合度，阈值 0.2 可配） |
| P4 | 每次进页面都是新会话 | 恢复最近一条未结束会话 + 「新对话」按钮 |
| P5 | 关单报"参数校验失败" | 关单改弹窗，结论必填、不填禁用确认 |
| P6 | 人工接管后客户不能打字 | ai_paused 语义是"AI 闭嘴"，不是"客户闭嘴"；新增 customer-messages 接口，消息直达客服不进模型 |

### 6.2 边界修改

原本定"客户侧不做多会话侧栏"，实际使用发现：客户会同时开多个会话，且转人工未被接单的会话会"消失"。现已改为：

- 客户侧有左侧会话列表（标题/状态/时间），默认打开最近一条进行中会话；
- 已结束会话可读不可写；
- 没有消息的空会话不再创建、不进列表，由清理任务回收。

### 6.3 新增的已知限制

| # | 限制 | 影响 | 缓解 |
|---|---|---|---|
| 8 | 客服侧的"实时流式"依赖进程内内存缓冲 | 多 worker 部署时客服看不到流式过程 | 当前单 worker；扩容时换 Redis 发布订阅 |
