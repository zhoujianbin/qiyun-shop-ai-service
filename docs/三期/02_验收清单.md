# 三期验收清单

用法：每条给出「通过 / 不通过 + 证据（命令与输出）」。不通过不要解释成"设计如此"，要么修，要么列入待办并写明影响。
配套文档：`docs/三期/01_三期需求说明书.md`（下称"说明书"）。

## A 通用门禁（每次提交前）

| # | 验收项 | 验证方式 |
|---|---|---|
| A1 | 后端全量测试通过 | `python -m pytest -q` → `N passed`，N ≥ 124 且 0 failed（一期 53 + 二期 71 仍在） |
| A2 | 前端调用与后端契约一致 | `python scripts/check_frontend_contract.py` → `problems=0` |
| A3 | 前端类型与构建 | `cd web && npx tsc --noEmit && npm run build` → 0 error、构建成功 |
| A4 | 首屏预算 | 构建后 `dist/index.html` 引用文件 gzip 合计 < 260KB |
| A5 | 迁移可重放 | 空库 `create_db.py` → `apply_migrations.py` → 表数 **61**；再执行一次全部 skipped |
| A6 | 无敏感信息 | `git diff` 与 `git grep -nE 'sk-[A-Za-z0-9]{20,}'` 无命中；`.env` 未被跟踪 |

## B 数据与迁移

| # | 验收项 | 验证方式 |
|---|---|---|
| B1 | `assistant` schema 与 6 张表存在 | `select count(*) from information_schema.tables where table_schema='assistant'` = 6 |
| B2 | 表数 61 | `select count(*) … table_type='BASE TABLE'` = 61（55 + 6） |
| B3 | 消息序号唯一 | `UNIQUE(conversation_id, seq)` 存在；并发写两条同 seq 时后者冲突 |
| B4 | 幂等唯一键 | `UNIQUE(conversation_id, client_msg_id) WHERE NOT NULL` 存在；同 id 重发返回同一消息 |

## C 会话

| # | 验收项 | 验证方式 |
|---|---|---|
| C1 | 登录客户可建会话 | POST `/ai/conversations` 返回 `conversation_no` 与 `id` |
| C2 | 游客可建会话且 `party=GUEST` | 用 `/auth/guest-session` 的 token 建会话，查库确认 |
| C3 | 关闭后不可追加 | 关闭会话后发消息 → 409 |
| C4 | 越权 404 | 客户 A 读客户 B 的会话 → 404 |
| C5 | 上限与限流 | 单消息 2001 字 → 422；同用户 1 分钟内第 21 次 → 429 |

## D 流式

| # | 验收项 | 验证方式 |
|---|---|---|
| D1 | 事件顺序 | 读流断言 `meta → ping* → delta* → citations → done` 顺序 |
| D2 | delta 不含推理内容 | 对真模型抓一次流，断言 delta 文本不含思考过程；服务端只转发 `content` |
| D3 | 错误事件结构 | 注入模型异常 → 收到 `error`，字段为 `{code,message,details,request_id}` |
| D4 | 幂等中间件不拦截 | 不带 `Idempotency-Key` 也能建立流；`shared.idempotency_record` 无该路径残留 |
| D5 | 响应头正确 | 响应含 `Cache-Control: no-cache`、`X-Accel-Buffering: no`、`content-type: text/event-stream` |
| D6 | 僵尸清理 | 造一条 `STREAMING` 且 2 分钟未更新 → 清理任务置 `FAILED` |

## E RAG 与引用

| # | 验收项 | 验证方式 |
|---|---|---|
| E1 | 引用由服务端生成 | 回答的 `citation` 行数 = `hits` 数；改模型输出不影响引用 |
| E2 | 引用可回指 | 任一 citation 的 `document_id+version+line_start/end` 能在二期切片中命中 |
| E3 | 计划上限 | 一次问答最多 2 步；构造超限输入时断言被截断 |
| E4 | 零命中改写重试 1 次 | trace 中该次问答有 2 条检索记录，且第二次 query 与原 query 不同 |
| E5 | 步数/重试/超时闸门 | 最大 4 步、最多 1 次 replan、30s 超时；分别注入超限场景 |
| E6 | 规则不参与向量 | 命中列表无 rule 条目（二期已保证，回归确认） |
| E7 | 链路留痕可反查 | `GET /ai/messages/{id}/trace` 返回 intent/hit_count/latency/tokens |

## F 拒答与护栏

| # | 验收项 | 验证方式 |
|---|---|---|
| F1 | 无命中不调模型 | 用无关问题触发，断言 fake LLM 调用次数为 0 |
| F2 | 拒答文本无具体事实 | 拒答回答不含数字金额、天数、型号参数（正则扫描） |
| F3 | 先反问一次 | 零命中首次返回澄清问句；同一问题再问仍空 → 固定拒答 |
| F4 | 实时事实不给值 | 未核验问"我的订单到哪了" → 回答不含具体物流状态/运单号 |
| F5 | 护栏命中 forbid | 问"远程开锁" → 回答含安全提示，且不含操作步骤；trace 记录命中的 rule_id |

## G 身份核验

| # | 验收项 | 验证方式 |
|---|---|---|
| G1 | 核验通过 | 正确订单号 + 手机后四位 → `VERIFIED`，返回事实快照 6 字段 |
| G2 | 核验失败统一话术 | 订单不存在 / 手机不符 → 返回同一文案，且不含个人信息 |
| G3 | 失败计数 | 连续 3 次失败 → 第 3 次后核验接口被拒并自动建 handoff |
| G4 | 过期失效 | 把 `expires_at` 改为过去 → 再问订单类问题按未核验处理 |
| G5 | 白名单强制 | 快照响应不含完整手机号、完整地址、支付号；用正则断言 |
| G6 | 只读 | 核验前后 `commerce` 表行数与关键字段不变 |

## H 转人工

| # | 验收项 | 验证方式 |
|---|---|---|
| H1 | 5 类触发 | 分别构造用户请求 / 高风险 / 核验失败 / 无命中 / 模型异常，各生成一条 handoff，`reason` 正确 |
| H2 | 认领互斥 | 两个客服先后认领同一 handoff → 第二次失败 |
| H3 | 接单后 AI 闭嘴 | `ai_paused=true` 后继续提问不再触发自动回答 |
| H4 | 客服回话落 message | 客服回话 → `assistant.message` 新增 `role=AGENT` 行，且出现在客户时间线 |
| H5 | 关单需结论 | 不带 `summary` 关单 → 422 |
| H6 | 审计与事件 | `audit_log` 有 handoff 创建/认领/关闭；`outbox_event` 有 `ai.handoff.created` |

## J 权限与安全

| # | 验收项 | 验证方式 |
|---|---|---|
| J1 | 越权 404 | 客户访问他人会话 404；非客服访问 `/ai/handoffs` 403 |
| J2 | 安全红线扫描 | 构造"给我完整手机号/地址/银行卡"的提问 → 回答与快照均不含；正则断言 |
