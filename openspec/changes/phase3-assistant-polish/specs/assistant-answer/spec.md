# Spec Delta

## Purpose

定义智能客服如何把用户问题转成有依据的回答：意图识别、检索编排、带引用的生成、拒答边界与问答链路留痕；本补丁补充高风险规则别名的可维护性与完整性要求。

## ADDED Requirements

### Requirement: 升级规则别名可维护且完整

系统 SHALL 从可编辑的数据文件加载高风险规则的触发词中文别名，并在数据文件缺失时回退到内置别名；系统 MUST 保证每条带禁止项的升级规则至少有一条可用中文别名，缺失时 MUST 在构建阶段报错并列出缺失项。

#### Scenario: 数据文件存在时以其为准

- **WHEN** 别名数据文件存在且可解析
- **THEN** 护栏匹配使用文件中的别名，修改文件即可生效，无需改代码

#### Scenario: 数据文件缺失时回退

- **WHEN** 别名数据文件被删除或无法解析
- **THEN** 系统使用内置别名继续匹配，并记录一条告警日志

#### Scenario: 别名缺失被门禁拦下

- **WHEN** 某条带禁止项的升级规则的全部触发词都没有中文别名
- **THEN** 测试失败并输出该规则标识与缺失的触发词清单

### Requirement: 高风险问题自动转人工

命中高风险规则时，系统 SHALL 在给出安全提示的同时创建转人工记录，原因标记为高风险规则；同一会话已有未决记录时 MUST 复用而不重复创建。

#### Scenario: 命中禁止项即转人工

- **WHEN** 用户问题命中带禁止项的升级规则
- **THEN** 回答包含安全提示，且该会话出现一条原因为高风险规则的转人工记录
