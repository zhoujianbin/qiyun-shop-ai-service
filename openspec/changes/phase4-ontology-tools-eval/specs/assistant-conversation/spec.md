# Spec Delta

## MODIFIED Requirements

### Requirement: 流式输出事件协议

回答 SHALL 通过服务端推送（SSE）分片输出，事件序列 MUST 依次为：元信息、（工具状态）、若干心跳、若干文本增量、（待确认动作或引用）、结束或错误；工具状态与待确认动作为可选事件，其余事件 MUST 保持既有顺序与载荷不变。服务端 MUST 每 15 秒发送一次心跳，响应 MUST 禁止缓存并关闭代理缓冲。模型的工具调用原始结构 MUST NOT 出现在任何事件载荷中。

#### Scenario: 正常流式

- **WHEN** 客户发起一次知识类问答
- **THEN** 客户端先收到元信息，随后收到文本增量，最后收到引用与结束事件

#### Scenario: 工具状态先于叙述

- **WHEN** 一次问答需要调用业务工具
- **THEN** 客户端先收到工具状态事件，随后才收到文本增量

#### Scenario: 待确认动作事件

- **WHEN** 模型触发写工具
- **THEN** 客户端收到包含动作标识、摘要、影响说明与过期时间的待确认事件

#### Scenario: 工具调用结构不外泄

- **WHEN** 抓取整条事件流
- **THEN** 任一事件载荷中都不包含工具调用的原始参数结构

#### Scenario: 流中断

- **WHEN** 生成过程中服务端异常
- **THEN** 客户端收到错误事件，且该消息状态置为失败

#### Scenario: 生成被截断

- **WHEN** 模型因长度上限被截断
- **THEN** 该消息状态置为失败，而不是结束为空的正常回答

#### Scenario: 心跳保活

- **WHEN** 回答生成耗时超过 15 秒
- **THEN** 客户端在文本增量之间收到心跳事件，连接不被中间层断开
