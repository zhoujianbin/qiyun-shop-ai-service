# Design — 三期缺陷修复

## Context

- 走查结论见 `proposal.md`；真实模型 + trial 库实测。
- 现有实现：`assistant_graph.classify()` 规则未命中即调 `llm.complete()`；`finalize()` 只看 `hits` 是否为空；`stream_message` 只在护栏/拒答时建 handoff。

## Decisions

### 决策 1：意图识别默认零模型调用

规则未命中直接返回 `KNOWLEDGE`（三期唯一可执行的路径就是检索）。

- 开关 `ASSISTANT_USE_LLM_PLANNER`（默认 `false`）；打开时才走原来的 LLM 分类。
- 为什么：三期没有工具，planner 除了增加 3–5s 首字延迟没有任何决策价值；四期有工具时再把开关打开。

**备选**：保留 LLM 但改成流式并发（复杂度高，本期不需要）。

### 决策 2：相关性闸门用关键词重合度，不依赖 debug 分数

- 问题切 2-gram，去掉停用 gram（什么/怎么/需要/可以…）。
- 取 top-1 命中的 `snippet + title_path`，统计共享 gram 数。
- 判定：共享 gram ≥ `ASSISTANT_RELEVANCE_MIN_OVERLAP`（默认 2）视为相关，否则整批命中作废 → 走"无命中"流程。
- 为什么不用 `debug` 分数：二期 spec 明确 `debug` 仅供调试、三期勿依赖；且 `fused_score` 是排名倒数不是相关度。

**代价**：启发式会误杀（例如口语化转述）。缓解：阈值可配 + 真实问句回归测试；误杀时走"澄清→拒答→转人工"，比给错引用安全。

### 决策 3：对话内转人工与其余触发共用同一入口

`create_handoff` 已有"同一会话只允许一个未决记录"的部分唯一索引，因此新增 HANDOFF 分支不需要额外幂等逻辑。

### 决策 4：别名表按"用户怎么说"补，不按"规则怎么写"

新增反向覆盖测试：为每条带 `forbid` 的 escalation 规则准备 2 条真实问句，必须命中护栏。这样别名缺口在 CI 里暴露，而不是等走查发现。

## Risks / Trade-offs

| 风险 | 缓解 |
|---|---|
| 相关性闸门误杀正常问题 | 默认阈值 2 个共享 gram；配 6 条真实问句回归；误杀退化为澄清+转人工 |
| 关掉 LLM planner 后意图精度下降 | 三期只有一条可执行路径（检索），精度无实际损失；四期按开关恢复 |
| 补别名引入过宽匹配（误报高危） | 别名只在 escalation 规则上生效，误报的后果是"多给一句安全提示"，可接受 |

## Migration Plan

- 无数据库变更。回退：删除新增配置项即回到旧行为（除 P0 修复外均有开关或可独立回滚）。
